The first push

Four steps to publish your project.

01 / PREPARE01

Initialize Git

Start tracking the project in this folder.

git init
02 / SAVE02

Commit your files

Stage your work, then save a snapshot.

git add .
git commit -m "Initial commit"
03 / CONNECT03

Set up GitHub

Create a remote repo and link it here.

git branch -M main
git remote add origin <url>
04 / PUBLISH04

Push it up

Publish the main branch for the first time.

git push -u origin main

After the first push

Repeat this loop whenever you make changes.

01 / REVIEW

Check your changes

See which files Git has noticed before staging them.

git status

02 / SAVE

Commit a snapshot

Stage your work and give the change a clear message.

git add .
git commit -m "Describe the change"

03 / SHARE

Push updates

Send your new commit to the connected GitHub repo.

git push

Tip: When connecting an existing local project, create an empty GitHub repository. Skip adding a README, .gitignore, or license on GitHub so the first push stays straightforward.

Undo changes

Choose the command based on what you need to undo.

Restore a file

Discard unstaged edits in a file and return it to the last committed version. This replaces your current edits.

git restore <file>

To unstage a file but keep its edits:

git restore --staged <file>

Revert a commit

Create a new commit that reverses an earlier commit. This preserves history and is the safer choice for changes already pushed.

git revert <commit-id>

Then share the new undo commit:

git push

Remember: restore changes files or staging; revert adds a commit to history. Check git status before undoing anything.
